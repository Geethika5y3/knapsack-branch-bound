How Branch-and-Bound works

  1. Sort the items by profit/weight ratio, highest first.
  2. Start at the root node: no items decided, weight 0, profit 0.
  3. Calculate the root's upper bound by filling the knapsack greedily and taking a fraction of the first item that does not fit.
  4. Pick the most promising live node, the one with the highest bound (best-first search).
  5. Branch on the next item: Include it (if it fits) or Exclude it.
  6. Calculate the bound of both children.
  7. Prune any node whose bound is less than or equal to the best complete profit found so far. It cannot beat the best solution.
  8. Repeat until no promising nodes remain. The best solution found is optimal.
Pseudocode 
sort items by profit/weight (descending)
best = 0
PQ = max-priority-queue ordered by bound
root = Node(level=0, weight=0, profit=0)
root.bound = Bound(root)
PQ.push(root)

while PQ is not empty:
    node = PQ.popMax()                // most promising node
    if node.bound <= best:            // cannot beat best solution
        prune(node); continue
    if node.level == n: continue      // leaf: nothing to branch
    item = items[node.level]

    include = Node(level+1, weight+item.w, profit+item.p)
    if include.weight > capacity:
        prune(include)                // infeasible
    else:
        best = max(best, include.profit)
        include.bound = Bound(include)
        PQ.push(include)
    exclude = Node(level+1, weight, profit)
    exclude.bound = Bound(exclude)
    PQ.push(exclude)

// Nodes whose bound is not above best are pruned when popped.

Bound(node):
    if node.weight > capacity: return 0
    b = node.profit; w = node.weight; j = node.level
    while j < n and w + items[j].w <= capacity:
        w += items[j].w; b += items[j].p; j++
    if j < n: b += (capacity - w) * items[j].p / items[j].w
    return b

Complexity

Time: O(2n) in the worst case, since every include/exclude combination could be explored. In practice the bound prunes many subtrees, so far fewer nodes are usually visited.

Space: O(2n) worst case for the live-node queue in best-first search. The tree shown here also stores every generated node.
